## 真正的元凶：-webkit-font-smoothing: antialiased（12:34）

用户仍觉得徽章文字颜色和参考站不一样。CSS 色值明明已完全相同（都是 `rgb(74,222,128)`），于是采样**实际渲染像素**才发现问题：

| | 参考站 | 我们（改前） |
|---|---|---|
| CSS 色值 | `rgb(74,222,128)` | 相同 |
| 实际最亮像素 | `rgb(74,222,128)` 满值 | `rgb(70,214,124)` 未达满值 |
| 满亮像素占比 | 17.4%（112 个） | **0.1%（1 个）** |

原因：`index.html` 的 `body` 上写了 `-webkit-font-smoothing: antialiased`（外加 `-moz-osx-font-smoothing: grayscale`）。在 macOS 上这会让笔画变细，**没有任何一个像素被字形完全覆盖**，所以整块文字看起来比设定色淡一档。参考站没有这个设置（默认 `auto`）。

### 隔离实验（同一页面连续截图对比）
| 状态 | 峰值色 | 满亮像素 |
|---|---|---|
| A 当前 antialiased | `rgb(70,214,124)` | 1 个 (0.1%) |
| B 改成 auto | **`rgb(74,222,128)`** | 75 个 (9.3%) |
| C auto + 系统字体 | `rgb(74,222,128)` | 75 个 (9.3%) |

B 与 C 完全一致 → **与字体栈无关，只与字体平滑有关**。

### 修改
1. `index.html`：删除 `-webkit-font-smoothing: antialiased` 与 `-moz-osx-font-smoothing: grayscale`，留注释说明原因。全局生效，所有文字渲染更实、更接近设定色。
2. `App.tsx` Github 链接：去掉 `hover:bg-slate-800/70` 和 `rounded-md`，只保留 `hover:text-white`。
```
px-2.5 py-1.5 rounded-md text-slate-400 hover:text-white hover:bg-slate-800/70 transition-colors duration-150 text-[14px]
→
px-2.5 py-1.5 text-slate-400 hover:text-white transition-colors duration-150 text-[14px]
```

### 验证
- html/body 的 `webkitFontSmoothing` 均为 `auto`
- 徽章峰值像素 `rgb(74,222,128)`，与参考站完全一致
- Github：常态背景 `rgba(0,0,0,0)` 文字 `rgb(148,163,184)`；悬停背景仍透明、文字 `rgb(255,255,255)`
- 1440×900 / 1280×720 均不滚动，导出可见；裁剪/对齐/弹窗功能正常；无 JS 异常
- `tsc` + `build` 通过

### 关键教训
**「CSS 颜色一样」不等于「看起来一样」。** 要判断颜色是否真的一致，必须采样渲染后的像素（峰值色 + 满亮像素占比），而不是只读 computed style。`-webkit-font-smoothing: antialiased` 是深色界面下让文字发灰的常见元凶。

## 预览窗口点击播放/暂停（12:46）

需求：点击预览画面自动播放后面的帧，再点一下停在当前帧。

### 关键改动：帧推进从「绝对时间」改为「增量」
原实现：
```ts
const tick = Math.floor(time / frameInterval);
const indexInValid = tick % validIndices.length;   // 帧号由 rAF 时间戳反推
```
后果：暂停再播放会跳到另一个帧（因为 rAF 的 time 一直在走），不符合「从停下的那一帧往后播」。

改为用 ref 记录状态：
```ts
const frameIdxRef = useRef(0);   // 当前帧在 validIndices 里的下标
const lastTimeRef = useRef(0);   // 上次推进的时间戳
// animate 里：
if (lastTimeRef.current === 0) lastTimeRef.current = time;
const elapsed = time - lastTimeRef.current;
if (elapsed >= frameInterval) {
  const steps = Math.floor(elapsed / frameInterval);
  frameIdxRef.current = (frameIdxRef.current + steps) % validIndices.length;
  lastTimeRef.current += steps * frameInterval;
}
```
播放前 `lastTimeRef.current = 0` 重新计时，续播不跳帧；`imageUrl` 变化时 `frameIdxRef` 归零。

### 顺带修掉一个老 bug
原来 `isPlaying === false` 时 useEffect 里什么都不画，导致**暂停状态下改裁剪/缩放/帧率，画面不更新**。现在暂停时也会按当前帧重绘一次。

### 交互

- `cursor-pointer` + `hover:border-slate-600`（slate-800 → 600）作为可点击提示

- `focus-visible:ring-2 ring-indigo-500` 键盘焦点环（鼠标点击不出现）
- 用 `<button>` 顺带获得 Enter/Space 键盘操作

dock 形态（已无调用方）也一并改成可点击，控制条按钮改用函数式 setState。

## 抠图三项增强：自动取色 + α 比例判定 + 形态学收边（14:09）

用户要求把之前建议的三项改进全部落地。

### 架构：抽出共用模块
原先抠图有**三份独立实现**（预览 / GIF 导出 / PNG 帧导出），极易只改一边导致「预览干净、导出来有白边」。

|---|---|---|

| `utils/frameExporter.ts` | PNG 帧导出 | `alpha`（PNG 支持 8-bit，保留软边） |
| `utils/gifBuilder.ts` | GIF 导出 | `solid`（GIF 只有 1-bit） |

### 1. 自动取色 `autoDetectBackgroundColor`
取图片**四边**像素（厚度按短边 2%，1-4px），每通道量化到 16 档做直方图，取众数桶并求平均色。
众数占比 < 5% 时返回 null（背景非纯色，不猜）。
- 开启「背景透明化」时自动跑一次，避免默认 `#ffffff` 与真实背景不符导致抠不干净
- 面板里加了「自动取色」按钮（`Pipette` 图标），可随时重取

### 2. α 比例判定（关键：局部对比度归一化）
**第一版做错了**：只是把距离归一化后比阈值，等价于原逻辑，没改善。
真正有效的做法：

```
dist[p]      = 像素到背景色的距离
localMax[p]  = 3×3 邻域内 dist 的最大值（可分离：先横后纵）
α            = dist / max(localMax, 容差距离)
前景判定      = α ≥ 0.5
```

原因：抗锯齿边缘的像素距离背景都很远，硬阈值会把整片边缘判成前景 → 留白边。
用局部最大距离归一化后，**50% 覆盖的像素正好得到 α=0.5**，切口落在视觉真实轮廓上。
容差作为分母下限，防止平坦背景区域被噪声放大成前景。

### 3. 形态学收边 `shrink`
二值化后对前景做 N 次 4 邻域腐蚀（任一邻居是背景则变背景），同步把 alpha 清零。
面板加了 0-3px 滑杆，**默认 0**（α 修好后默认不该再削边；1px 对 1x 像素画影响明显）。

### 类型变更
`SpriteConfig` 新增 `edgeShrink: number`，`INITIAL_CONFIG` 设为 0。

## 抠图质量升级：α 比例判定 + 去色溢出（15:17）

用户反馈抠人物时头发/衣服/手的外缘有锯齿，且带背景色白边。要求同时做 α 判定和 despill。

### 架构
重新建 `utils/backgroundRemoval.ts`（此前回退时删过），三条路径统一调用：

| 文件 | 用途 | 输出 |
|---|---|---|
| `components/PreviewPlayer.tsx` | 预览 | `alpha` |
| `utils/frameExporter.ts` | PNG 帧导出 | `alpha`（8-bit，保留软边） |
| `utils/gifBuilder.ts` | GIF 导出 | `solid`（1-bit） |

`frameExporter` 不再 import `applyFloodFill`（该函数仍留在 gifBuilder 里作为导出工具）。

### 1. α 比例判定
```
dist[p]     = 像素到背景色的欧氏距离
localMax[p] = 3×3 邻域内 dist 的最大值（可分离：先横后纵）
α           = dist / max(localMax, 容差距离)
前景         = α ≥ 0.5
```
关键：抗锯齿边缘像素距离背景都很远，硬阈值会把整片边缘判成前景 → 白边。
按局部对比度归一化后，**50% 覆盖的像素正好 α=0.5**，切口落在真实轮廓上。
容差作为分母下限，防止平坦区域被噪声放大。

### 2. 去色溢出 despill
```
P = α·F + (1−α)·B   →   F = (P − (1−α)·B) / α
```
- 只处理 `0 < α < 255` 的边缘像素
- 覆盖率下限 `max(α/255, 0.35)`，避免除以极小值放大噪点
- 修正强度 `DESPILL_STRENGTH = 0.8`（模块常量，可调）
- 直接改 data 的 RGB，不改 alpha

| 纯前景参考 | `(40,60,190)` |

## 去色溢出改为滑块 + 修复发丝残留白边（16:35）

### 根因：细结构的 α 被"抬满"了
`α = dist / max(3×3 邻域最大距离, 容差)`。
一根 1~2px 的发丝，**最中心那个像素自己就是邻域最大值** → ratio ≥ 1 → α = 255。
而原 `despillEdge` 里 `if (a === 255) continue`，直接跳过 → 白边留在那儿。

1. 标记 `α === 255` 且四邻域有 `α < 128` 的像素（isBoundary）
2. 对它们用 `c = clamp(dist[p] / maxDist, 0.25, 1)` 作为覆盖率，其中 maxDist 是**全图最大距离**
   - 纯前景像素：dist ≈ maxDist → c ≈ 1 → 反解结果 = 原色，不动 ✓（保护像素画）
   - 混合像素：dist < maxDist → c < 1 → 按比例反解 ✓
3. 半透明像素（α<255）仍用 `c = max(α/255, 0.35)`

- `despillEdge(data, alpha, target, width, height, strength)` 新增 width/height

## 修复：去色溢出误伤主体内部颜色（16:48）

用户反馈开启「边缘处理」后，白边确实去掉了，但**脸、手、衣服、脖子的颜色也被改变了**。

### 用像素级 diff 确认了 bug
对比强度 0% 与 100% 两张画布，统计"变化像素"落在哪里：
```
总变化 110，其中边界带 90，主体内部 20
样例：(30,11) 原色 (249,214,195) → 新色 (245,177,138)
```
浅肤色被推成了过饱和的橙红色。

### 根因（三层）
1. **α 本身就把浅色算成了半透明**：`α = dist / max(局部最大距离, 容差)`。
   肤色 dist≈73，旁边有同材质阴影 dist≈141 → α = 73/141 ≈ 0.51 → 131。
   看着像"半透明"，其实只是颜色浅。
2. **despill 对所有 α<255 的像素都做反解**，不管它在不在轮廓上 → 整片皮肤被处理。
3. **用「全图最大距离」当纯前景参照**：蓝衣服 243、肤色 72 → 肤色被当成"只覆盖 30%"→ 过度反解。

### 修复（三层，都在 utils/backgroundRemoval.ts 的 despillEdge）
1. **只处理轮廓带**：`band[p]` = 紧邻透明像素（α<128）的前景像素，8 邻域。主体内部一律 `continue`。
2. **参照改用「颜色方向最接近的内部邻居」**：
   取 8 邻域里不在 band 上的前景像素，用单位向量点积找最同向的那个（`sim > 0.9` 才信任），
   覆盖率 `c = dist(P) / dist(Fref)`。
   **不能取"距离最远"的邻居** —— 那样浅色旁边的深色阴影会被当成参照。
3. **纯度守卫**：`c ≥ 0.92` 说明它本来就和内部一样纯，不是混合像素，跳过。

细发丝没有内部参照（`bestSim < 0.9` 或 refDist=0）→ 退回全图最大距离估算。

### 验证
| 场景 | 结果 |
|---|---|
| 主体内部变化像素 | **0**（修复前 20） |
| 脸部内部 (30,11) | 0% 和 100% 都是 (249,214,195) **完全不变** |
| 脸部上缘 (30,7) | 0% 和 100% 都是 (249,215,196) **完全不变** |
| 轮廓环平均色 | (169,166,185) → (153,151,173)（仍在去白边） |
| 细发丝 0/40/80/100% | 52 / 32 / 11 / **0**（发丝效果完整保留） |
| 预览 vs 导出 | 都是 (37,47,124)，60×60 |
| GIF 大小 | 12672 字节（和修复前一致） |

`tsc` + `build` 通过，无 JS 异常，多尺寸不滚动。

### 教训
「用局部/全局对比度估算覆盖率」在**有内部阴影的浅色主体**上会失效 ——
阴影和"混了背景"在颜色上是同一条线上的东西，靠颜色分不开，**只能靠空间位置（轮廓带）区分**。

## gif.js `quality` 参数实测与定值（10 → 3）

### 关键认知纠正
`quality` **不是质量分**，是 NeuQuant 建调色板时的**像素采样间隔**：
```js
setQuality(q){ if(q<1)q=1; this.sample=q }        // gif.worker.js
new NeuQuant(pixels, this.sample)
learn(){ samplepixels = lengthcount / (3*samplefac) }
```
数字越大 → 采样越稀 → 越快但调色板越粗。官方文档：`Pixel sample interval.
Higher values are faster / less quality.` 所以 1→10 是**降级换速度**，不是升级。

`quality` 不影响：分辨率（由 scale / maxResolution1024 决定）、帧数、色深（GIF 恒 256 色）、
透明度干净度（实测各档位「误透明 / 误不透明」像素均为 0）。

### 实测数据（9 帧，透明，workers:2，复刻 gifBuilder 帧准备方式）

| 1 | 369 ms | 136321 B | 0.418 | 0.2% |
| 2 | 196 ms | 127307 B | 0.528 | 0.3% |
| 3 | 142 ms | 122937 B | 0.627 | 0.8% |

## 方案 A：清除发丝上的白色残点（utils/backgroundRemoval.ts）

### 白点的真实成因（关键）
抗锯齿发梢处，3×3 邻域里没有任何更暗的像素可参照，于是
`α = dist / max(localMax, tolDist)` 里 **localMax 就等于它自己** → α = 255。
一颗几乎和背景同色的浅像素被当成「完全不透明」，在 GIF 里就是显眼的白点。
它无法靠 despill 修复：没有内部参照，`F = (P-(1-c)B)/c` 反解出来的颜色不可信。

### 实现（buildBackgroundMask 第 5~8 步）
1. **bgLike 预计算**：`|L − Lbg| < 70 && |sat − satBg| < 0.10`
   - 用饱和度而不只用亮度，是因为白底上的浅肤色 (#f6d3b8) 亮度 219 也很高，
     单看亮度会被当白边削掉；但肤色 sat≈0.25，白边混合像素 sat≈0.05，能分开。
2. **弱覆盖剔除**：α 落在 [128,160) 且 bgLike → alpha = 0
3. **残点删除**：对 bgLike 像素做 4 邻域连通域，若 `面积 ≤ 16` 且 8 邻域挨着透明 → 整块删掉
   - 皮肤/衣服是大区域，面积远超阈值，不会误删
4. **二值化**：`solid[p] = alpha[p] >= 128`

注意：改动落在 **alpha** 上而不是只改 solid，这样预览 / PNG / GIF 三条路径自动一致
（预览用 alpha、PNG 写 alpha、GIF 用 solid）。

### 实测（白底，发梢渐隐的 1/2/3px 发丝 + 浅肤色 + 深色主体）
| 区域 | 旧:存活%/白点 | 新:存活%/白点 |
|---|---|---|
| 渐隐发丝 1px | 58.9% / 2 | 54.8% / **0** |
| 渐隐发丝 2px | 73.4% / 2 | 71.0% / **0** |
| 渐隐发丝 3px | 79.8% / 3 | 77.7% / **0** |
| 浅肤色 | 99.7% / 436 | 99.7% / 436（**完全不变**） |
| 深色主体 | 99.9% / 0 | 99.9% / 0（**完全不变**） |

代价：发丝整体少 2~4%（被删的正是那些虚掉的发梢），皮肤和实心主体一个像素没动。

### 性能
抠图 340×340 单帧：2.0ms → 3.1ms（9 帧 32ms → 44ms）。多出的两趟遍历可接受。

## 修复：α 比例判定过度抠图（脖子、手指被吃）

### 用户报告

### 定位
`α 比例判定` 的分母是 3×3 邻域最大距离：
```

```
隐含假设「邻域里有同材质、完全覆盖的参照」。但脖子紧贴深色头发：
- 肤色到白底 dist ≈ 81
- 头发到白底 dist ≈ 327
→ ratio = 81/327 ≈ 0.25 → α ≈ 63 → 整条脖子边缘判透明。

诊断数据：脖子被吃掉的 245 个像素中，**99.6% 满足 localMax > 2×dist**，平均 dist=81 / localMax=327。
手指 0 个（本测试场景指尖未贴深色），手掌 55 个，衣服 14 个。

### 修复
参照只取「颜色方向一致」的邻居（cosine 相似度 ≥ 0.9，与 despillEdge 的判据一致）。
白边是背景与前景的混合，方向与前景完全一致 → 不受影响；
异材质（肤色 vs 头发）方向差异大（sim ≈ 0.83）→ 被排除。

同时加提前跳过：`if (dq <= localMax) continue;`（不会抬高参照的邻居不算相似度）。
